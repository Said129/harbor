# Music playlist export

The production playlist page now offers Export. It resolves every member of the stored playlist in order, independently of the current search, source, genre or sort filter, then presents the native Files exporter. Empty playlists produce the original `#EXTM3U` header. Missing metadata or an unresolved source fails the complete export rather than silently shortening it. A success notice uses the exported snapshot's name and count.

The original inputs are authenticated in `music-playlist-export-inputs.json`. Desktop resolves each track with its normal playback resolver and writes extended M3U entries with duration, artist, title and resolved location. The native implementation uses the actual owned `MusicPlaybackSession` resolver without starting audio. Local entries use the imported file's actual path. The format replaces CR/LF in artist and title, rejects empty or multiline locations, preserves Unicode and unsigned durations, and derives the filename from the playlist name. Rendering and encoding run on a background actor.

The active profile and caller's playlist permission are checked before and after each asynchronous resolution and after rendering. Every returned stream lease must remain valid at the end, including the earlier ones. Cancellation, deletion or profile departure cannot return a newly prepared document. The interface cancels pending preparation when it leaves. After the user hands an export to the operating system's document picker, that external copy is under their control. The export is an explicit user action; no file is automatically uploaded or shared.

The existing resolver currently supports genuine imported audio, direct URLs and the connected Subsonic service. Future provider work must extend that resolver rather than introduce export-only substitutes. An M3U contains locations rather than copies of the audio, so a local app-container path is useful on its originating installation and does not make that audio portable. Resolved provider URLs have the same service access and expiration requirements as the Desktop output.

Desktop's shared Subsonic resolver schedules its optional now-playing report when resolving a stream, including for export; the native shared resolver retains that behavior. Export does not load audio or submit completed listening scrobbles. Its new integration case uses an owned loopback publisher rather than external provider credentials.

Four new native cases are prepared: extended format and filename edge cases; the actual owned Subsonic/local-import session exporting the full list; held resolutions with retired permissions, cancelled tasks and expired earlier leases; and 64 comparisons for three original labels plus one translated native error in all 16 languages. They have not executed in Apple. The original Rust and DOM modules have not been executed for this feature; no original-runtime comparison is claimed. Ordinary Files picker navigation, the new action's rendered phone/tablet layout and physical-device behavior still need review.

M3U import, the existing 500-track native playlist/queue/import limits compared with Desktop's larger library, and complete Music styling and provider parity remain open. This export implementation does not claim to complete them. Previously approved unrelated checks are retained. The live cover/cache run is pinned to an earlier source and cannot validate this addition. No IPA is requested here.
