# Desktop per-title and card artwork

Reference: Desktop 0.9.132 commit `0834340cec5531650bfe78cd628628702e636987`, `logo.ts`, `curated-logos.ts`, `title-{logo,poster,backdrop}.ts`, `tv-card.tsx`, TMDB image-language/image/anime modules and the media gallery.

TV cards now resolve missing logos and anime backgrounds independently of catalog loading. The native resolver coalesces identical requests, bounds the provider concurrency and memory cache, reuses the existing static anime-art index, prefers curated/own logos unless localized TMDB artwork is requested, and falls back through Cinemeta, verified anime aliases/Kitsu, TVDB artwork and the original ranked TMDB anime search. Derived SPECIAL/OVA/ONA/MUSIC titles skip the TVDB series fallback and require exact TMDB title matching. Anime formats survive the existing AniList/Jikan/MAL/Kitsu parsers. Unsupported media kinds do not invoke movie/anime artwork providers. Late card responses cannot publish after the view changes title, settings or active profile.

The original `tmdbImageLangs` preference is available as ordered language chips, including Original, with add/search/reorder/remove and persistence in the existing profile snapshots. The metadata language remains independent. TMDB language parameters, logo language/PNG/vote scoring and anime title/year/Japanese-animation ranking are compared against fixture output from thirteen cases executed through the five actual pinned TypeScript modules. Test doubles replace settings/network/cache registration only; no provider request runs in the reference extractor. Native tests remain separate evidence.

The media gallery adds the original per-title logo/poster/backdrop toggle. Selecting the same image again resets that override. The maps use the original storage names, support JSON strings/data/dictionaries and belong to the active shared or independent profile snapshot. Cards, primary content/detail heroes and Continue Watching consume the overrides. Image overrides preserve media identity, playback and episode order. Native tests exercise these maps and profile changes; the new gallery pin buttons still need direct runtime interaction evidence before full-port approval.

Only TMDB request variants place the configured API key on the fixed TMDB host. Public curated, Cinemeta, anime, mappings and TVDB requests receive no TMDB key in their URL. Cache configuration keys are digests, and private settings are not bundled into the app. Anonymous Windows GET observations on 2026-10-26 found the community art index available with 6,325 entries and the Dragon Ball Super TVDB artwork response containing backgrounds and clear logos. The curated-logo endpoint currently returns an empty object; normal fallbacks continue. These observations do not prove native transport success; a new native public request test verifies that path separately.

The prior appearance run `40308939041` executed thirteen cases: five native and four fresh preparations passed; the iPhone appearance route passed functionally; three interfaces failed. Its 23 original images were individually reviewed. That review also found Center text was still left aligned in both TV grids. Caption alignment now follows the original center/end positions, and fitted logos preserve their aspect ratio and logical leading alignment inside a clipped viewport. A new UIKit layout test covers this renderer; the existing default artwork renderer and approved bitmap tests stay intact.

Selection `affected:card-artwork`: eight new native tests, six fresh guest preparations, two new image-language routes, three failed source/appearance routes and the affected iPhone appearance route: twenty executions and 44 required original screenshots. Five approved appearance native tests and the six source native tests are retained. The new interface route renders an owned pinned catalog card, checks Original/default order, searches/adds Spanish, moves it, removes Original and checks persistence after relaunch. Source dialogs explicitly contain accessibility children; source-specific gestures use visible viewports, and appearance scrolling uses the outer gutter rather than the interactive seek preview. Every required original screenshot still needs inspection after execution. No IPA is built by this selection; focused/expanding/dock card animations, fallback settings samples, portrait poster localization and the remainder of the full port remain pending.
