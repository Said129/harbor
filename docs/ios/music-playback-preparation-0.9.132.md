## Request and profile ownership

`MusicPlaybackSession` prepares actual Subsonic or explicit stream URLs and owner-scoped local-file lookup. It commits full recording metadata using the shared playlist document before returning a stream, as Desktop's resolver remembers a recording before playback. Failed writes retain the previous document and reject admission. The returned lease checks both profile activation and private credential revision; a retired lease cannot admit playback. A playlist store belonging to another owner is rejected.

`MusicPlaybackItem` can carry a shared recording and an optional genuine imported local record. It does not fabricate a local filename for a remote song. `MusicListening` preserves the original event increment rule and half-duration/four-minute scrobble threshold. The preparation suite has three cases: session/metadata ownership, listening rules and the native header contract below.

`MusicStreamHeaders` validates Desktop's limits of 16 headers, 128 bytes per name and 8,192 bytes per value. It sends a native mpv string array, preserving commas, quotes and backslashes, handles User-Agent separately and clears prior headers when the next source has none. One of the three preparation cases reads the result back from a real initialized libmpv instance. This is a header contract test, not a playback test. Five original Rust module inputs are authenticated in the adjacent input record; their complete Rust implementations were not executed by this slice.
