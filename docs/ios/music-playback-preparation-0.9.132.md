# Shared music queue and playback preparation

This slice prepares the shared player to accept server recordings alongside local files. It does not yet replace or connect the existing local-only `MusicPlayback` engine. No audio, ordinary navigation or full Music parity claim follows from these helpers.

## Complete Desktop queue logic

`MusicQueueOrderAssets.json` contains the complete original `src/lib/music/queue-order.ts` class compiled from the pinned Git blob, plus a typed JSON adapter. Program SHA-256 is `304e9e0a23fe198a59959cb9cb1b09cfc9228d026f72aa5c219341fb09ab391f`; its source is 8,443 bytes. The native JavaScriptCore wrapper verifies that digest before executing it and passes JSON as an argument. Network, credentials and player commands stay outside the context.

An independent Node fixture executed the complete original class and compared the adapter across 610 states in ten scenarios: sequential/repeat/shuffle, priority, history and forward navigation, modified queues, empty input and collection-source identity. The native two-case test exercises those same state sequences in Apple JavaScriptCore and the typed API/error recovery. Optional absent/null track fields are compared as typed recording metadata. These native cases have not run yet.

The algorithm determines a stable shuffle permutation before advancing, so the future player can share it with the upcoming list. It also retains Desktop's collection-origin queue keys, manual/automatic repeat-one distinction and shuffle Previous/forward behavior. The adapter retains the existing native 500-item admission limit; this is not a new certification of every Desktop library capacity limit.

## Request and profile ownership

`MusicPlaybackSession` prepares actual Subsonic or explicit stream URLs and owner-scoped local-file lookup. It commits full recording metadata using the shared playlist document before returning a stream, as Desktop's resolver remembers a recording before playback. Failed writes retain the previous document and reject admission. The returned lease checks both profile activation and private credential revision; a retired lease cannot admit playback. A playlist store belonging to another owner is rejected.

`MusicPlaybackItem` can carry a shared recording and an optional genuine imported local record. It does not fabricate a local filename for a remote song. `MusicListening` preserves the original event increment rule and half-duration/four-minute scrobble threshold. The preparation suite has three cases: session/metadata ownership, listening rules and the native header contract below.

`MusicStreamHeaders` validates Desktop's limits of 16 headers, 128 bytes per name and 8,192 bytes per value. It sends a native mpv string array, preserving commas, quotes and backslashes, handles User-Agent separately and clears prior headers when the next source has none. One of the three preparation cases reads the result back from a real initialized libmpv instance. This is a header contract test, not a playback test. Five original Rust module inputs are authenticated in the adjacent input record; their complete Rust implementations were not executed by this slice.
