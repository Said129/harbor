# Desktop household profiles: work in progress

Reference: Desktop 0.9.132, source `0834340cec5531650bfe78cd628628702e636987`.
This belongs to the existing full iPhone/iPad port. It does not reserve or create another IPA.

**Scope update, 2026-10-18:** the owner explicitly excluded child profiles and the Kids section. Their interfaces, parental controls, daily limits and artwork will not be ported. The unintegrated daily-budget source and its eight pending cases have been removed without dispatching a budget validation. Normal household profiles remain in scope. Portable Desktop metadata and existing device credentials remain intact for synchronization compatibility; their presence is not an exposed child-profile feature.

The local foundation and initial application routing have been written. All 55 new native cases passed against application source `49110c6786903d6480c2febe101d8210f2a4fb9b` in [run 39119398009](https://github.com/Said129/harbor/actions/runs/39119398009): 15 roster/lock/routing cases, eight session migration cases, eight context cases, three library binding cases, three playback ownership cases, nine settings cases and nine roster synchronization cases. The affected paused-resume playback case also passed; the affected PiP case was skipped by the simulator and remains unverified. No new warning messages were introduced. **This proves those model cases, not the full profile interface or physical-device behavior. Startup binds the migrated primary profile; the multi-profile selector is not yet exposed.**

`NativeProfileRoster.swift` separates the portable Desktop roster from device identity, Stremio sharing, migration ownership and credentials. Unknown Desktop fields survive adoption and editing. Portable output omits device IDs, passwords, parent PINs and Stremio sharing IDs. Profile names alone never establish that existing user data is disposable.

`HouseholdProfileStore.swift` commits the roster, selection, routing and device locks together in Keychain. Missing remote rows are retained; explicit deletion creates tombstones. Incoming account revisions cannot move backwards. Linked settings share one scope; independent settings use the personal scope. Continue Watching remains shared unless the private option is enabled and two profiles actually share the same Stremio source, matching `cw-profile.ts`.

Selection checks credentials centrally. Reloading or locking the session invalidates prior unlocks. A failed persistence write cannot publish an unlocked selection. Unsupported Desktop profile fields and previously saved credentials are retained as compatibility data. Child content and playback restrictions are excluded from application integration by the owner's scope update.

`DeviceProfileCredential.swift` uses device-specific random salt and PBKDF2-HMAC-SHA256 through Apple's [CommonCrypto API](https://github.com/apple-oss-distributions/CommonCrypto/blob/main/include/CommonKeyDerivation.h). Derivation runs away from the main actor. The independently calculated test vector, fresh-salt checks and real PIN verification passed on Apple in run 39119398009. Credentials remain device-local, as required by Desktop's `WireProfile` contract.

`HouseholdSessionVault.swift` prepares actual Stremio session isolation. A shared Stremio source reads the same account; an independent source starts with its own account configuration. The old iOS session and its migration claim are committed together, preserving the complete saved addon payload. Legacy keys are retained for rollback but cannot silently sign a profile back in or migrate into a different household. A generation and per-source version reject late login/refresh writes after source changes. `AppProfileContext` now connects the vault to `AppModel`; this is source integration, not a claim that live account switching has been verified.

The root keeps content hidden until account, settings, library and resume storage are bound. The migrated profile retains the previous reading, favourites and tracker namespace; new profiles receive independent personal scopes. Reading shelves, music, downloads, discovery and seasonal preferences now use that scope. Shared Stremio library records keep their source account. Linked navigation, streaming services and TV settings use the household settings owner. Private Continue Watching and full Harbor identity/roster transport still require integration before exposing the selector.

`ProfileSettingsStore` mirrors Desktop's shared and independent settings documents for the existing native preferences. It snapshots the old role and prepares the new role in one Keychain commit before changing the active defaults. A new independent role forks shared values; an existing role retains its own changes. The legacy mirror can be claimed only once. A failed write leaves the previous role visible, and restart loads the saved document rather than an interrupted mirror. Appearance, player, stream and metadata-language singletons reload without writing fallback values over their stored document. Root changes are coalesced for 250 ms; profile changes and backgrounding flush pending edits. Device consent, account tokens and onboarding state are outside this mirror.

TMDB keys remain in the Keychain settings document, outside UserDefaults. Initial migration reads the previous key only while claiming the original shared role; later roles never automatically reread it. Independent roles start with the shared key and can change or remove their own copy. The metadata editor captures its settings owner before verification and rejects a late save after the role changes. All nine settings cases passed in run 39119398009, including secret migration, isolation, failed saves and stale editor ownership. Actual profile settings and secret transport have not yet been wired to the full Harbor household service.

Open EPUB/PDF requests are queued at the stable application root, including cold starts. A request opened for a specific profile waits for that profile rather than being imported into whichever person is selected later. The actual UI flow remains to be verified.

`ProfilePlaybackRegistry` closes registered video/PiP controllers during a context change and rejects late surface creation. A rejected controller cannot initialize its renderer or audio session later. The context changes its operation token even when two people share Stremio; addon refresh completions cannot clear a newer task or publish an old error. The three registry cases and the context cases passed on Apple in run 39119398009. Actual PiP startup remains unverified because the separate affected playback case was skipped by the simulator.

Signing in or out of a shared profile follows Desktop's `auth.tsx`: detach that profile from its shared source. `prepareOwnAccount` durably stages its own account before the caller changes `shareStremioWith` and binds the new source. Refreshing the deliberately shared addon/source configuration remains a shared update. The primary source is never replaced or signed out by a secondary profile's explicit sign-in/sign-out.

The device's Harbor identity is anchored with the original session migration and survives later Stremio logins or deletion of the original profile. Backfilling an older session record requires the exact original migration route and an atomic write. Account UI, synchronization polling, navigation and service settings use this stable identity; personal appearance remains in the active person's namespace. Harbor-scoped households use separate shared settings owners. This prepares the global identity routing only: full household roster adoption, profile metadata editing and account transitions still require integration and verification.

`HarborHouseholdSync` prepares the full `account:profiles` document engine using the existing Harbor revision protocol. It parses a complete state before seeding, binds one explicit Harbor account, journals a pending write before POST, and recognizes an accepted write after a lost reply and restart. Edits made during POST remain pending at the acknowledged revision. Concurrent first uploads retain missing local profiles and the server's primary profile. Stale replies and failed persistence cannot acknowledge the current journal. Portable profile and roster numbers use the same JSON representation before storage and server comparison, avoiding false changes after decoding. All nine model cases passed in run 39119398009. **The engine is not yet connected to the authenticated transport or final selector.**

Validation run `39117565521` stopped before any tests because Swift could not type-check the long root view expression in `HarborApp.swift`. The root was split into content, persistence, lifecycle, synchronization and account presentation expressions while retaining the stable startup and document-open handlers. The corrected source compiled on Apple in run 39119398009. No IPA was generated.

Later source work adds `HouseholdProfileDraft` and an atomic `saveEditor` operation: identity, sharing, settings, device credentials and the initial selection are committed together after derivation. Failed storage or a context change during derivation cannot publish a partially configured profile. Existing secondary profiles can edit their identity; management of other profiles and advanced options follows the primary-profile restrictions in Desktop's editor. Six new transaction cases and two affected existing cases passed on Apple in [run 39145711513](https://github.com/Said129/harbor/actions/runs/39145711513), against application source `b0649c025dc92cc92370c548953a68b78d3bfed9`, without new warnings. This includes a historical child-credential compatibility case; it does not authorize a child-profile interface. Earlier unchanged cases retain their exact source provenance.

`ProfilePINEntryView` prepares the shared set/confirm/verify screen with a 48-point numeric keypad, hardware-keyboard input, PIN indicators, wrong-PIN feedback, the reference shake and entrance timing, RTL labels and Reduce Motion. It delegates verification to the real store operation, invalidates a dismissed request and does not persist plain PINs. Hardware input uses Apple's [onKeyPress](<https://developer.apple.com/documentation/swiftui/view/onkeypress(characters:phases:action:)>) and focus APIs. The source compiled on Apple in run 39145711513. **This component is not yet connected to the final selector/editor or visually verified on Apple.** It is not a claim that profile UI parity is complete.

Before claiming profile parity, complete and verify:

- Transactional migration of existing iOS sessions and data, with Stremio sharing or separate accounts following the selected profile.
- Actual routing of reading, favorites, trackers, discovery, settings, library and optional private playback progress; changing a profile must change the data being used.
- Full roster synchronization and durable queued changes through the existing authenticated Harbor transport.
- The normal profile selector, editor, optional profile PIN entry and linked settings on iPhone and iPad. Do not add child-profile creation or a Kids destination.
- Original normal-profile picker artwork, configurable backgrounds, Desktop transitions and Reduce Motion behavior.
- Focused Apple tests and manual inspection of actual phone/tablet screenshots. Previously approved unrelated checks remain reusable only when their producers are unchanged.

The original foundation-only review is historical. The updated context routing inventory and exact source hashes are saved outside the app in `work/harbor-revision/parity132/profiles/context-routing-review.json`. These are implementation inventories, not a completion percentage or runtime proof.
