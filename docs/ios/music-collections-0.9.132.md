# Music saved tracks and listening history

The 0.9.132 reference has three main Music tabs: For you, Explore and Library.
The current native Music screen exposes the local library. Online discovery,
connectors and their interfaces still require their own comparison and port;
this increment does not establish full Music parity or full application parity.

The local library now includes the original permanent saved-track collection
and recently played collection, accessible with playlists. Track context menus
save or unsave a track and the row displays its saved status. Each collection
can be searched and played using the existing native music queue. Unsave keeps
the audio file, playlists and recent history. Missing local files do not create
playable rows; their saved identities remain available for a later reimport.

Desktop `music/store.rs` orders likes by the latest save and keeps fifty distinct
recent tracks, newest first. Replaying a track moves that identity to the front.
The native adaptation preserves this order and limit and writes history after an
actual mpv FILE_LOADED event, outside the event processing loop. Metadata import
or a failed file open does not record playback. Saved membership uses a cached
set so track rows do not scan the entire saved collection when rendering.

Storage is keyed by personal profile in this device's protected Keychain. Reads
validate the original document before enabling writes. Updates publish only after
storage succeeds. A read, validation or write failure preserves existing data and
appears in Music with retry. The user interface uses the original Desktop labels
and generated language catalogs. These local collections do not claim remote
Spotify or Stremio synchronization.

Three new native cases cover the fifty-track order, replay and profile isolation,
restart, failed storage and invalid data, and actual owned audio playback through
mpv. Two fresh UI journeys save a real imported track, play it, open the recent
collection and unsave while verifying that history remains. The selection has
seven executions and eight captures. Existing complete music playback tests and
unrelated reader tests are retained. Actual Apple outcomes and visual review are
pending; no IPA is generated by this validation.
