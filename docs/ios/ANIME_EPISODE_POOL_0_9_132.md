# Source-aware franchise episodes — implementation awaiting Apple validation

This increment follows Desktop 0.9.132's `anime-franchise-episodes.ts`, `anime-episode-build.ts`, `use-franchise-episodes.ts`, `anime-slot-match.ts` and `use-anime-watched-routing.ts`. It belongs to the full agreed functional, visual and animation port. It does not produce an IPA or certify the whole port.

`AnimeEpisodePool` combines real current-entry and other eligible Kitsu season episodes in a separate catalog. It deduplicates per source and verified provider pair and keeps Desktop's pair/absolute sorting and current-entry tie priority. Each episode carries its real source metadata ID. Raw video IDs, season/episode coordinates and each source media's original video-array order are retained. The combined array never becomes a source's watched-bitset array. Different sources' raw `S1E1` or even identical video IDs have different navigation keys.

The public entry loader reuses existing anime metadata, verified AniZip enrichment and optional TVDB stills. The shared metadata-gate implementation bounds concurrent entry pipelines at four even across overlapping callers. Successful public entries are coalesced and cached separately from account/addon metadata. Failures remain retryable without discarding successful entries. The cache retains at most 24 entries and 30,000 episode rows, and skips caching an individual oversized series while still returning it intact. None of these limits proves physical-device speed. Current entries and scoped Bleach parts keep their existing behavior; movies/specials are still separate work.

The TVDB projection now matches verified episode IDs, exact provider pairs and explicit franchise-wide absolute numbers. A pair-correct episode takes priority over a stale mismatched TVDB ID, as in Desktop. Claimed episodes cannot fill a second slot. Known foreign TVDB series remain outside that order's ordinary slots. Conflicting pairs inside one source stay ambiguous; overlapping source entries retain insertion priority. A cour's unverified local `1...12` never becomes the franchise's global `1...12`. Provider slots without a real source remain explicitly unmatched, rather than becoming invented playable IDs.

AniZip enrichment preserves Desktop's duplicate-ID, same-season shift and scoped Hunter x Hunter defenses. It retains verified external IMDb coordinates separately from raw local playback/watched coordinates. Stream and subtitle queries can use a verified external pair even when the local cour number differs. Legacy unverified mismatches remain rejected.

Detail streams and playback sessions capture the actual selected source media. Resume lookup, subtitles, player title, downloads, discovery and progress writes use that source. The detail and player episode lists resolve watched/spoiler state per source. Adjacent episodes can cross a mapped season boundary without collapsing two local `S1E1`s. New public pool results are discarded after cancellation, entry changes or the same owner's profile activation changes. Public loading does not block the current entry's usable list. Row rendering uses precomputed source identities; full projection of a source's video array is reserved for selection/session creation.

Eleven new native cases cover source-array/bitset preservation, cross-cour navigation, duplicate video IDs across sources, per-source resume/watched behavior, stale and foreign TVDB identity, explicit absolute numbers, mapping defenses, bounded/coalesced partial recovery, actual session/resume/subtitle routing and profile-activation races. Thirteen existing native cases are selected because their projection, sequence, mapping or stream/subtitle producer changed. The existing public episode-99 adapter is selected for the changed mapping algorithm. Other approved suites and the whole graph suite are excluded. Compilation and all 25 selected executions are pending; the new source-aware views and playback transition still need real iPhone/iPad visual/runtime review.

Still required for full anime fidelity: movie/special matching and buckets, missing provider-slot playback routing where supported by actual source data, season-specific hero artwork, foreign-season windows beyond known series identity, remaining XML mapping fallbacks, persistent root caching, optional private TVDB/TMDB choices and full interface/motion review. Account/realm/profile synchronization and all other pending Desktop sections remain part of the full objective.
