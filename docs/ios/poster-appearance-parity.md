# Desktop poster appearance on iPhone and iPad

Reference: Harbor Desktop 0.9.132, commit `0834340cec5531650bfe78cd628628702e636987`, particularly `theme-panel/display/poster-card-section.tsx`, `poster-options.tsx`, `components/tv-card.tsx` and settings defaults.

The existing media cards now consume the same six setting names: `rowCardStyle`, `tvCardLogoPos`, `posterScale`, `posterRadius`, `posterEffect`, `posterQuality`. The settings view uses the original six size presets, continuous 0–40px radius and five nearest-radius labels, three TV logo positions, three load effects and three image qualities. Changes follow shared/independent native profile snapshots. Appearance reset restores the six default values as well as the existing palette/font/seek color.

Portrait and TV cards share fallback artwork, titles and the existing portrait rating badge policy. TV cards render wide backdrop art when present or a blurred poster with the original gradient, miniature poster and title/logo. Rows, Top Ten and eight media grids consume the style and scale. Responsive grid widths clamp to the actual available container, including iPad windows; the ranked text list preserves its portrait layout. Reduce Motion suppresses load transitions. Missing images finish their transition and show the fallback placeholder. Missing-logo and anime backdrop resolution beyond already supplied metadata, focused cards, expanding backdrops and dock magnification still require implementation; this change does not complete all appearance parity.

Static ImageIO thumbnail creation now runs in a detached, cancellable worker and eagerly decodes pixels before returning the immutable bitmap to the main actor. High/Balanced bound decode dimensions; Maximum reads the original image dimensions. Network fetch and fallback policies are retained. This is an implementation improvement, not a measured physical-device performance result.

Source UI repairs address the actual failures from run `40244262302`: the provider folder's accessibility identifier no longer overwrites the nested catalog scroll identifier, and import/cover/GIF URL fields have an accessible clear button. UI interactions use that real button rather than relying on iOS URL-selection menus. Shared previously approved interaction helpers are unchanged.

Validation selection `affected:poster-appearance`: five new native tests (configuration/profile isolation and real bitmap decoding), two previously failed source interface tests, two new appearance interface tests and four fresh guest preparations: 13 executions, 36 required original screenshots. The appearance routes exercise real settings, rendered grid dimensions, all six choices, persistence after relaunch and reset on iPhone/iPad. Prior six approved source native cases and unaffected earlier results remain valid. The URL import/edit/relaunch source flow remains required.

Local checks and selection preflight do not prove Apple compilation or runtime success. Apple results and all original screenshots must be inspected before this block is approved. This validation creates no IPA; the full port still requires its remaining features and one final validated IPA.
