# Original recording and source-selection policy

The native source-selection adapter runs the original pure functions from
Desktop's source-version, queue-source, sources and play-track modules. It
preserves requested credits when audio comes from another provider, original
queue identity, first-ranked alternatives per service, offline-source handling,
preferred-source ordering and vocal/instrumental/karaoke compatibility.

The builder authenticates the four inputs against commit
0834340cec5531650bfe78cd628628702e636987, permitting only checkout line-ending
normalization. It compiles the complete pure modules and extracts the original
headless resolver's selection statements. The Apple adapter verifies the
program digest before creating a local JavaScriptCore context. Inputs are JSON
arguments to a function, never executable interpolation. The context receives
no provider credentials, network implementation or native player commands.

headless resolver with owned candidate replies and an owned player callback.

after an invalid operation. Both passed in Apple run 40864283892 at source

No visual captures were required; this proves the decision and bridge behavior,

This is the shared selection policy, not the complete source-picker interface
or provider resolver. Real provider search, connection management, playback,
loading/recovery interfaces and the mixed-playlist surface still require their
native integration. No live provider or audio request is made by the reference.
