# Manga and Books interpreted sources

The Plugins settings now include Streams, Manga, and Books. The reading kinds have separate repository and installation records, browsing and refresh, install/update/remove, enable/disable, and Mangayomi JavaScript bulk installation. The existing Suwayomi route remains the compatible route for Android extensions. Desktop itself filters Dart sources from this JavaScript index.

Ten pinned reference inputs supply the original manga result/header adapters, Books metadata/content/volume parsing, repository classification, Mangayomi index expansion/deduplication, and its complete DOM/crypto/runtime prelude. `ReadingPluginAssets.json` contains trusted adapters and a composer; downloaded source is only data in that context. Installed providers run in separate existing WebKit workers. Normal source calls use the reference method arguments and budgets. Manga IDs use the reference aggregate `source::item` form; Books use its encoded `source:plugin:…` provider routes.

Manga sources now reach the ordinary source picker, search, details, chapters, page renderer, progress, and page export. Books reach the source picker, search, the ordinary reader, chapter navigation, bookmarks, position saving, narration, and image chapters, including the original missing-content-method fallback. Extra metadata is retained in saved items. Existing PDF/EPUB/local folders and Gutenberg services are unchanged.

Each profile activation gets a new session while installation data remains local to the device, as in Desktop. Profile retirement cancels source work and disposes its workers and caches. Calls share the eight-operation gate; at most four idle source workers are retained. Public artwork downloads coalesce within the activation and use a bounded 32 MB/80-entry cache. Page headers retain the original allowed fields and 6,000-entry bound. Book covers are reduced off the UI actor before display.

## Validation and limits

Twenty-two original adapter/composer cases executed successfully in Node. Four new native models cover those actual worker comparisons, installation and complete source/reader contracts, Mangayomi execution/concurrency, and retirement during installation. Two fresh guest preparations and two new iPhone/iPad UI routes produce sixteen original captures and two recordings. The images are served on loopback from an existing repository-owned fixture, without a production test mode or external-provider dependency. The loopback server has been exercised locally; that is not native test approval.

Apple SDK compilation, all eight executions, and original visual/motion review remain pending. This block does not certify all reading parity: manual HTML source editors, combined Books source catalogs and filters, reading synchronization, and the wider Desktop interface/settings/motion audit remain separate work. No IPA or full-port completion is implied.
