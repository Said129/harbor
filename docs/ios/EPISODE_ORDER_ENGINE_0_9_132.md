# Episode-order engine — work in progress

Reference: Desktop 0.9.132, commit `0834340cec5531650bfe78cd628628702e636987`, specifically `src/lib/providers/tvdb.ts` and `tvdb-order.ts`.

The native engine now represents Aired, DVD, clean Absolute, raw TVDB Absolute, Alternate and Regional order. It discovers advertised orders, checks whether they contain episodes, reads their pages through the existing public metadata transport, and builds season buckets with counts and date ranges. Requested text falls back per field to English and then the provider's original text. The existing bounded response cache and request coalescing are reused.

Clean Absolute joins regular episodes in canonical broadcast order and excludes specials. Raw TVDB Absolute preserves the provider's sequence, including specials. Ordered slots retain canonical and alternative coordinates separately. Duplicate IDs are placed once; duplicate canonical pairs use unique alternative pairs for presentation while keeping their original canonical reference. Playable `Episode` IDs, watched-bit ordering, streams and resume records are untouched by this component.

Nine new XCTest cases cover the six modes, discovery and shared requests, requested/English/original text, season names and dates, language mappings, duplicate IDs/coordinates and bounded pagination. The `episode-order` CI scope selects those nine cases only, authenticates the actual Xcode result tree, preserves partial failure evidence and disables IPA packaging. Synthetic provider replies test the new engine; they do not establish public-service availability or visual parity.

These are component results, not approval of the later panel integration.

The subsequent panel integration connects real provider episodes to the detail selector and the player, preserves the original source-array order for watched bits, and passes a separate projection to previous/next/start navigation. The panel includes order tabs, season rows, counts, date ranges, current-month/ongoing indicators and a collapsible extras section, with a sheet on compact displays and a popover on iPad. Rich-panel and order preferences belong to each normal profile. Labels are added from the pinned Desktop catalogs; all existing labels remain unchanged.

Canonical source identity is retained for specials even when a DVD order places them inside a regular season. Four new projection cases and one profile-isolation case cover this integration; five existing cases are selected again because their navigation/canonical-identity producer changed. Unrelated suites and the unchanged nine-case engine suite are not repeated. Two new ordinary public interface journeys exercise Aired → Absolute → Aired on iPhone/iPad, expecting eight original images and two recordings. Actual execution and visual review of this integration remain pending.

This is not complete episode parity. Unmatched TVDB slots are explicitly recorded without manufacturing playable video IDs. Cross-entry anime franchise pooling, movie/special source routing, foreign-season exclusions, the optional personal TVDB key and TMDB provider choice remain to be ported. The panel currently projects episodes already supplied by the selected real media entry; preserving that fallback is not a substitute for completing the full franchise system. The full functional/visual/animation Desktop port remains active, no new IPA is created here, and the previous conversational 75% is not an audited completion metric.

Local Python compilation, scoped selection generation and preservation of all existing labels in 16 native catalogs pass. `pnpm run check` can format the changed JSON/YAML/Markdown, but Swift/Python have no supported lint targets in this repository. Earlier unrelated successful tests remain retained. The full Linux-build limitation on Windows is unchanged; no TypeScript or Rust product code changed in this increment.
