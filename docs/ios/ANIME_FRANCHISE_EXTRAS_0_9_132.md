TVDB slots can now reference a real extra entry from the franchise. Matching uses the reference's decomposed Unicode title normalization, then a release-date difference of at most one day. Only extras are eligible and an entry is claimed once per order. A real provider episode takes priority over a similarly named extra. `EpisodeOrderSection.rows` preserves the mixed provider order, including a movie between DVD episodes; the section count includes both row types. Extra rows never become fabricated stream IDs or enter an existing source's watched-bitset array.

Detail and player lists display linked movies/specials with their metadata, loading state, availability, spoiler preferences and real watched actions. Selecting one resolves actual public addon metadata before opening its stream picker. The movie or OVA uses its own media ID, provider video/default-video ID, IMDb fallback, subtitle request, resume and watched record. The main series stays open behind that picker. Unknown entries, mismatched metadata, cancelled requests, owner changes and profile-activation changes cannot publish a selection. A failed lookup leaves the available series usable and reports a contextual error.

The entry metadata cache also accepts non-episodic movies and shares the existing bounded/coalesced public loader. It contains no personal addon URLs or account credentials. Movies avoid optional episode-mapping and episode-still queries. Current anime movies and one-video entries use the reference's large artwork card, play action, watched badge and season selector. A known multi-episode series is not classified as a movie merely because its metadata is partially loaded. The iPad pointer interaction respects Reduce Motion. Movie/one-off playback does not show the episode-navigation controls intended for a series. Ordinary movie playback and older episode-coordinate source IDs remain available.

Older builds could store a movie under the provider's raw `S1E1` position. `ResumeStore.position` can reuse that entry only for the same actual movie and video, preserving newer explicit restarts and keeping the original key intact. Series never use this fallback. Cloud resume accepts the same implicit movie identity when an older record contains an episode-shaped video array. The download player passes its stored metadata through this same movie-resume path. Raw source arrays, unrelated episode positions and other owners' stores stay separate.
