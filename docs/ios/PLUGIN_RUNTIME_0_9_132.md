# Native interpreted plugin foundation — Apple execution pending

The native port now includes the pinned Desktop worker, HTML serializer and provider compatibility programs from `0834340cec5531650bfe78cd628628702e636987`. `build-plugin-runtime-assets.mjs` verifies all six inputs against their Git-verified LF-normalized SHA-256 values, transpiles the TypeScript data modules and stores three executable programs in a JSON resource. Each program carries a semantic source hash checked again by Swift before injection. JSON formatting does not alter the stored program strings. The reference source files and the historical Desktop frontend are unchanged.

`HarborPluginRuntime` creates an ephemeral WebKit host and a dedicated worker. Installed code executes through the original worker's init/call/result/cancel protocol. The host uses the original bounded DOM serialization for HTML and the reference provider prelude for CommonJS, DOM helpers, crypto, Buffer and configured values. The page blocks ordinary network/resource loading; HTTP/gRPC messages go through an injected native `HarborPluginHostTransport`. Calls use request deadlines, per-instance identity and owner/activation guards. Cancellation discards late results; timeout, scope change, disposal and content-process termination reject pending operations. Each worker admits six host requests and the shared gate admits sixteen, matching the reference host limits. Logs are bounded and discarded at disposal. A weak script-message handler avoids a controller/runtime retention cycle.

Four new Node executions passed on the Windows development host: declared methods/arguments, provider helper/settings isolation, HTTP/gRPC message and byte contracts, and cancellation suppressing a late result. They use owned synthetic data and no actual provider network. The Node harness was subsequently formatted with no behavioral changes; those results are retained. They do not prove execution inside iOS or correct behavior of a public installed plugin.

Seven native Apple contracts are prepared: actual WebKit HTML handling; provider compatibility and per-instance settings; HTTP/gRPC bridge and local/global concurrency; cancellation and subsequent reuse; stale owner/activation rejection; a busy worker timeout alongside another usable worker; initialization and missing-method failures. These SDK executions remain pending. The host JS resource is explicitly packaged by XcodeGen, and the Swift loader checks both resource availability and program hashes.

This is an implementation foundation for the required Plugins room, not its completion.
